04 · Asynchronous authorization
The agent asks.
You authorize.

Client-Initiated Backchannel Authentication (CIBA) separates the request from the approval experience.

1
Agent requests authorization from Auth0.
2
Auth0 emails a link to the user’s verified email.
3
User opens the browser, authenticates if needed, and approves.
4
Backend observes approval; only then may the action run.
Email delivery is not itself MFA. Add step-up requirements when the stakes demand stronger assurance.
[19:30–20:30 elapsed · 11:34 AM CT–11:35 AM CT] Describe CIBA as asynchronous authorization, not automatically a biometric step-up. Email can be opened on the same device; it is a separate flow, not proof of a separate trusted device. Auth0 supports custom policy and MFA. CIBA features require Enterprise or an appropriate add-on. Sources: https://auth0.com/docs/get-started/authentication-and-authorization-flow/client-initiated-backchannel-authentication-flow/email-notifications-with-ciba, https://auth0.com/ai/docs
